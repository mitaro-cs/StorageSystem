# Безопасность

## Как сообщить об уязвимости

Пожалуйста, **не публикуйте уязвимость в открытых issue**. Сообщите приватно через
[GitHub Security Advisories](https://github.com/mitaro-cs/StorageSystem/security/advisories/new)
(«Report a vulnerability»). Опишите, что можно сделать, как это воспроизвести и какая версия
затронута. Мы ответим в течение недели и договоримся о сроках исправления и раскрытия.

## Поддерживаемые версии

До выхода 1.0 исправления выпускаются только для последней версии из ветки `miaro`.

## Модель угроз вкратце

groupbase хранит учебные данные группы на её собственном сервере. Мы защищаемся от:

- **чужих из интернета** — вход по паролю (Argon2id) с ограничением попыток и нарастающей блокировкой,
  обязательная 2FA для администраторов, код первичной настройки только в логе сервера;
- **участников других групп того же сервера** — права проверяются на сервере для каждого запроса,
  изоляция групп покрыта тестами, включая поиск, уведомления и офлайн-синхронизацию;
- **кражи файлов с диска** — файлы зашифрованы AES-256-GCM, ключи отдельно в `data/secrets`
  (или в переменных окружения);
- **XSS и CSRF** — Markdown очищается на сервере, CSP без inline-скриптов, CSRF-токен
  double-submit, cookie `SameSite=Strict`;
- **SSRF через push-подписки** — сервер отправляет уведомления только на домены служб push из
  настроек.

Вне модели: администратор сервера (он видит всё по определению), скомпрометированное устройство
пользователя, атаки на хостинг и ОС.

## Что проверяется автоматически

В CI на каждый коммит: тесты прав и изоляции групп, статический анализ, `npm audit` и
[osv-scanner](https://github.com/google/osv-scanner) по зависимостям Maven и npm.
